# 依赖安全补丁说明

核验日期：2026-10-04。适用于本仓库的 pnpm 12.4.1 锁文件和 CI，不代表运行中的服务器已经更新依赖。

## 已发布修复版本

`brace-expansion` 的 1.x、2.x、5.x 分别固定为 1.1.20、2.1.6、5.0.11，保留原主版本。1.x/2.x 经 ExcelJS 的归档、文件匹配依赖引入；5.x 经 Nest CLI 引入。

依据：[GHSA-qhr7-859c-m2p7](https://github.com/advisories/GHSA-qhr7-859c-m2p7)、[GHSA-6j4f-fj2g-mc7p](https://github.com/advisories/GHSA-6j4f-fj2g-mc7p)。安装前，三个版本的重复嵌套/逗号组输入均已复现 `Maximum call stack size exceeded`。

## braces 的临时本地补丁

[GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) 对 `braces <=3.0.3` 报告递归栈溢出。截至核验日，npm 最新版本仍是 3.0.3，官方公告没有已发布修复版本。[上游问题 #70](https://github.com/micromatch/braces/issues/70) 建议限制嵌套深度；[修复 PR #72](https://github.com/micromatch/braces/pull/72) 仍未合并。

本仓库通过 `patches/braces@3.0.3.patch` 对发布版增加固定 100 层上限：

- `parse` 对花括号和圆括号的嵌套计数，不把转义、引号或字符集内的字面量当作嵌套。
- `compile`、`expand`、`stringify` 对直接传入的 AST 同样限制递归深度。
- 超限抛出明确的 `SyntaxError`，不再走到原生堆栈耗尽；保留原 `stringify` 的父节点和转义语义。

这是本仓库维护的缓解补丁，不冒充上游正式修复，也不更名包或伪造版本。它覆盖本公告所述嵌套深度问题，不声称解决任意手工循环 AST、展开结果数量或所有拒绝服务输入。

## 唯一审计例外与强制验证

`pnpm-workspace.yaml` 的 `audit.ignore` 仅列 `GHSA-vfj7-8cjw-p6xm`。该例外以本地补丁和强制回归为前提，不能单独复制到没有补丁的项目。其他公告和注册表访问错误仍须使 CI 失败，不启用 `--ignore-unfixable`、`--ignore-registry-errors` 或整类 high 放行。

CI 依次执行：

```sh
corepack pnpm install --frozen-lockfile
node --test scripts/dependency-security.test.mjs
corepack pnpm audit --prod --audit-level high
```

回归从 ExcelJS、Nest CLI、uni-app 的实际依赖路径加载库，验证三条 brace-expansion 版本线、braces 的 100/101 层边界和 4,000 层攻击输入、直接 AST、转义兼容、实际文件匹配及内存 Excel 读写。删除补丁后，深度保护测试必须失败。

未配置例外时，升级并应用补丁后的原始 `pnpm audit --prod --audit-level high` 仍为 **退出 1，1 项 high**，因为审计按 `braces@3.0.3` 的版本识别，无法识别本地代码补丁。配置例外后的通过只表示“其余 high 告警通过，且该公告已按本地补丁策略验收”，不能表述成“上游已无漏洞”。原始结果留存在本地验收证据 `dependencies/audit-after-patch.json`。

补丁的兼容验证另覆盖官方发布源码 [74b2db2938fad48a2ea54a9c8bf27a37a62c350d](https://github.com/micromatch/braces/tree/74b2db2938fad48a2ea54a9c8bf27a37a62c350d) 的 764 项原测试，全部通过。应用自身的业务和发布验收仍由对应检查负责。

另外已在无 `node_modules` 的隔离目录复制同一 manifests、锁文件、补丁和测试脚本，完成冻结安装 998 个包；随后 8 项回归全部通过，审计明确报告上述唯一 ignored high。验证不依赖原工作区已经修改过的安装目录。

## 复核与移除

由维护依赖升级的开发负责人在每次正式发布前检查官方公告及 npm 修复版本；首次复核最迟为 2026-10-11。官方修复发布后，验证兼容性，升级到正式修复版本，并在同一变更中移除本地 patch、`patchedDependencies` 和这一项 `audit.ignore`。若补丁安装或强制回归失败，该例外不可用于发布放行。
