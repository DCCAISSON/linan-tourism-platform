## 推荐开发位置

不要求完全基于腾讯云开发。清理C盘后，推荐采用“C盘本地主开发 + 私有Git同步 + 腾讯云联调和部署”：

- C盘内置NVMe作为主工作区，完成编码、依赖安装、自动化检查、微信模拟器、真机预览、调试与上传。
- 腾讯云可同时承载远程开发、联调、测试数据库和正式部署；开发、测试与生产资源分别配置。
- Cloud Studio或独立开发云服务器作为可选远程开发入口，本地C盘仍保留完整Git工作副本。
- E盘修复后只作为可选的备份、归档或可重建缓存位置，不作为项目开工前置条件。

## 腾讯云开发与数据存储

可以在企业购买的腾讯云资源上开发，但“都在腾讯云”不等于“都放在同一台服务器或同一块磁盘”。首期按以下边界配置：

| 资源 | 用途 |
| --- | --- |
| Cloud Studio或独立开发云服务器 | 云端编码、构建和联调；不得兼作生产服务器 |
| 生产云服务器 | 运行API、管理后台和Nginx |
| 腾讯云数据库MySQL 8.4 LTS | 保存订单、报名、用户和配置等结构化业务数据 |
| 腾讯云对象存储COS | 保存图片、协议附件、导出文件等对象文件 |

上述资源由企业腾讯云账号持有，尽量选择同一地域；云服务器与云数据库放在同一VPC内通过内网通信，COS选择同地域存储桶。开发、测试和生产必须使用不同的数据库、COS存储桶和访问凭证，开发环境不复制真实生产客户数据。

企业首期采购中的生产云服务器与腾讯云数据库MySQL是两个独立产品，需要分别下单和计费；COS可先开通并按实际用量计费。Cloud Studio或开发云服务器不属于生产环境必购项。

## E盘当前阻断项

2026-09-14复核结果：E盘是通过USB连接的 `Seagate BUP Slim`，物理磁盘状态为Healthy，但NTFS卷被标记为Dirty，`Get-Volume`显示 `Warning / Full Repair Needed`。只读 `chkdsk E: /scan` 无法创建快照并要求离线修复。

这不等于硬盘已经损坏，但在修复完成前，不把Git工作副本、Docker磁盘或MySQL开发数据迁入E盘。E盘修复不再阻断本项目在C盘开工。后续处理顺序为：

1. 先备份E盘现有重要文件。
2. 关闭占用E盘的程序后，以管理员身份运行 `chkdsk E: /f`；按Windows提示卸载卷或重启检查。
3. 确认 `fsutil dirty query E:` 不再报告Dirty，且 `Get-Volume -DriveLetter E` 恢复Healthy。
4. 修复后如需使用E盘，从私有Git远端新建辅助副本，不直接剪切当前 `.git` 目录。

腾讯云 Cloud Studio 支持浏览器开发、Git导入、终端和独立工作空间，可用于当前项目。若需要持久在线开发与联调环境，可改用独立开发云服务器；开发环境不能与正式生产服务器共用。

参考：[Cloud Studio产品文档](https://cloud.tencent.com/document/product/1039)、[腾讯云数据库MySQL](https://cloud.tencent.com/document/product/236)、[私有网络VPC](https://cloud.tencent.com/document/product/215/20046)、[对象存储COS](https://cloud.tencent.com/document/product/436)。

## E盘修复后的可选用途

- 保存已经进入私有Git或其他备份介质的项目辅助副本，E盘不得成为唯一副本。
- 在C盘空间再次不足时存放可重建的pnpm缓存、构建缓存和测试素材。
- 图片、视频和活动照片不在本地长期保存，开发期使用少量虚构样本，生产使用COS。
- npm缓存和Docker资源只在确认没有其他项目依赖后清理；本次初始化没有自动删除任何缓存、镜像或数据卷。
