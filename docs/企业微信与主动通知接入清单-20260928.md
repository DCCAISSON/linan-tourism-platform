# 企业微信与主动通知接入清单

更新日期：2026年9月30日。

已通过微信接口在本小程序“旅行社”类目添加三类订阅模板：订单支付成功通知、订单待出发提醒、出行通知。实际模板ID及字段已写入本机私有接入文件，服务端通道已开启；测试团期有三份明确标注“联调”的内容版本，尚未建立发送任务或发送消息。下面模板选用步骤已完成，下一步是本人手机保存接收人、逐项同意订阅，再进行测试发送。集合模板没有车牌字段，正式使用时应通过通知跳转查看分车详情，不将车牌塞入其他字段。

## 一、平台功能的启用结论

|平台功能|本项目结论|当前动作|
|---|---|---|
|小程序订阅消息|需要启用|在公共模板库选择报名/支付、行前信息、车辆或集合变更三类正式模板，并真机授权、发送和核对结果。|
|小程序客服|需要启用，作为当前首选客服|在小程序后台绑定客服账号；小程序活动详情和订单详情已使用`button open-type="contact"`接入，客服人员使用网页端或移动端客服工作台接待。|
|微信客服（企业微信）|按运营需要选配|只有需要跨小程序、公众号、网页等统一接待时再开通；届时再配置CorpID、客服链接和企业微信接待人员。|
|小程序插件|不需要开通|本项目没有向其他小程序提供插件，也不依赖第三方小程序插件。|
|虚拟支付|不要开通|研学、旅游和出行服务属于线下真实服务，继续使用已经接通的普通微信支付；虚拟支付不适用于本项目商品。|

当前最短路径是先启用“小程序客服”，无需企业微信CorpID，也无需为人工接待配置消息服务器。管理员在“小程序客服”中绑定客服账号后，使用[网页端客服](https://mpkf.weixin.qq.com/)或移动端客服工具接待；消息服务器只在以后需要自建API客服系统时配置。

### 类似品牌小程序的主动触达怎么做

可以做，但家长侧应使用**小程序订阅消息**，不依赖企业微信客服。适合本项目主动发送的内容包括：报名或支付结果、行前资料发布、集合地点或车辆变更、退款结果等与本次服务直接相关的通知。

用户必须在小程序内主动点击并同意订阅；一次性订阅通常是“一次授权对应一次服务消息”，需要在报名、支付、查看行前信息等真实业务动作附近再次取得授权。待支付订单已经提供“订阅订单通知”入口，可在付款前取得报名/支付结果模板授权；付款后的行前和变更通知继续使用订单详情中的通知入口。后台只能给已经授权的接收人创建发送任务，不能凭手机号群发，也不能把服务通知改成无关的营销广告。具体规则以[微信小程序订阅消息说明](https://cloud.tencent.com/document/product/1301/103770)和公众平台当前模板库为准。

## 二、再区分四种业务通道

|能力|服务对象|本项目现状|下一步|
|---|---|---|---|
|小程序订阅消息|家长及其他实际接收人|授权、内容版本、任务、发送适配器和结果记录已有|在小程序后台取得正式模板并做真实手机送达验收|
|小程序客服|家长主动咨询|活动详情和订单详情入口已接入，尚未绑定客服账号并真机收发|在小程序后台绑定客服人员，用官方客服工作台完成一轮收发|
|微信客服（企业微信）|跨渠道主动咨询接待|本轮不作为上线前提，尚未配置CorpID和客服链接|需求方确认统一企微接待后再开通|
|企业微信客户联系|已经添加企业成员的微信客户|CRM与咨询已有，尚无企业客户身份同步|启用客户联系、配置可用成员及回调，再把`external_userid`人工关联到CRM客户|
|企业微信内部应用消息|导游、运营、管理员等内部员工|尚无真实企业应用通道|需要时创建自建应用，用于内部待办和异常提醒，不用于替代家长订阅消息|

企业微信不能直接向任意小程序用户主动发消息。家长通知以小程序订阅消息为主；微信客服要求家长主动进入会话；客户联系要求家长先添加企业成员。三者不能互相冒充已经送达。

## 当前线上核查结果

截至2026年9月28日，线上API中4个团期的微信通知均显示`wechatConfigured=false`，正式订阅模板为0，已启用服务端客服入口为0。服务端已有订阅授权、发送任务和结果记录代码，但尚未配置微信公众平台模板ID。小程序原生客服按钮已加入活动详情和订单详情，仍需在公众平台绑定客服账号并真机收发；企业微信客服的CorpID和客服链接仅在后续选择该方案时需要。

可以使用我们自己的微信测试，但应至少准备两个微信账号：一个个人微信充当家长/客户，另一个已在小程序后台绑定的客服微信账号负责接待。个人微信必须是当前小程序体验成员，并在业务页面主动同意订阅；客服账号需已完成小程序客服绑定。只有选择下文的企业微信客服方案时，接待账号才必须是企业微信成员。

## 三、需求方管理员现在需要完成的配置

### 1. 小程序订阅消息

1. 登录[微信公众平台](https://mp.weixin.qq.com/)，选择“临安旅游通”小程序。
2. 左侧进入“功能 → 订阅消息”。若新版菜单折叠在“基础功能”下，先展开“基础功能”，再点“订阅消息”。
3. 打开“公共模板库”，按“报名、支付、出行、集合、车辆”等关键词搜索；选中模板后点“选用”。不要先创建与业务无关的模板凑数。
4. 回到“我的模板”，依次复制模板ID，并展开查看字段名、字段类型和顺序。优先确定三类通知：报名/支付结果、行前信息发布或变更、车辆或集合安排变更。
5. 把模板ID和全部字段写入`private/企业微信与通知接入.local.md`。不要只写中文含义，必须保留平台字段名，例如`thing1`、`time2`。
6. 开发方在服务器开启订阅通道，并在管理后台“通知管理”中按平台字段创建通知内容版本；页面路径使用小程序现有页面，不填写外部网址。
7. 个人微信测试支付结果通知：将自己的微信加入小程序体验成员，扫描体验码进入；创建待支付订单后先打开订单详情，点击“订阅订单通知”，保存当前微信为接收人，再对报名/支付结果模板点“订阅通知”，在微信弹窗中选“允许”；随后完成支付并核对手机是否收到结果消息。
8. 个人微信测试行前和变更通知：付款后从“我的订单 → 查看订单详情 → 通知授权与接收入口”进入，对行前、车辆或集合变更模板分别授权。工作人员再在管理后台“通知管理”中选择对应团期和内容版本，创建任务、选择已授权接收人并发送。手机收到消息后核对后台结果；接口返回成功只能记为“接口已受理”，不能写成“已读”。

自己的个人微信可以作为家长测试，不需要另买账号。每种一次性订阅通常需要在真实业务动作附近由用户主动同意，后台不能替用户勾选，也不能只凭手机号发送。

### 2. 小程序客服（本轮采用）

1. 在微信公众平台进入“基础功能 → 客服”，在“小程序客服”一栏点“查看”。
2. 可以先绑定自己的个人微信。添加或绑定实际客服人员的微信账号，由该微信确认，再登录[网页端客服](https://mpkf.weixin.qq.com/)或微信内的“客服小助手”接待。个人微信在这里是客服人员身份，家长通过小程序客服会话联系，不等于加为私人好友。依据[微信客服消息使用指南](https://developers.weixin.qq.com/miniprogram/introduction/custom.html)，本轮已读取官方原文。
3. 不启用消息服务器也可以先使用官方工作台人工接待；只有以后需要自建API收发时才填写消息服务器配置。
4. 将新小程序版本设为体验版后，用个人微信进入活动详情或订单详情，点“联系客服”，发送一条带活动卡片的测试消息。
5. 客服人员回复，核对个人微信能收到回复、客服能看到正确活动或订单来源。

### 3. 微信客服（企业微信，可选）

1. 用企业管理员登录[企业微信管理后台](https://work.weixin.qq.com/wework_admin/)，进入“应用管理 → 微信客服”。首次使用时按页面提示开通。
2. 点“创建客服账号”，填写对外名称和头像；在该账号的“接待人员”中添加实际负责回复的企业微信成员。
3. 在微信公众平台进入“功能/基础功能 → 客服”，选择“微信客服”并按页面提示关联同主体企业；如果平台要求企业管理员确认，由企业管理员扫码完成。
4. 在企业微信“我的企业 → 企业信息”复制企业ID（CorpID）；在微信客服账号详情复制客服链接，链接通常以`https://work.weixin.qq.com/kfid/`开头。
5. 将CorpID、客服账号名称、客服链接、接待人员、工作时间和离线方式写入`private/企业微信与通知接入.local.md`。
6. 开发方使用小程序原生`wx.openCustomerServiceChat`接入CorpID和客服链接；Secret不会写进小程序。
7. 真机验收时，个人微信作为家长从小程序点“联系客服”并发送一条带活动名称的测试消息；企业微信接待成员收到后回复。核对双方能收发、入口指向正确客服账号、非接待人员不能查看会话。

可以在同一部手机上测试，但需要两个身份：个人微信负责发起咨询，已加入企业的企业微信成员负责接待。若只有一个人，可以在微信与企业微信两个App之间切换。

基础接入只需小程序点击时调用微信客服并传入CorpID和客服链接，不需要把企业Secret放入小程序。若以后启用API管理客服会话，再增加服务端凭据和回调。

### 4. 企业微信客户联系与CRM

1. 在“客户联系”中配置可使用成员和可调用应用。
2. 确认是否需要“联系我”二维码/链接、添加客户事件、客户标签及离职继承。
3. 若需要系统同步，提供客户联系Secret，并为回调生成Token与EncodingAESKey。
4. 回调地址由开发方部署后再填写；不得把Secret、Token或EncodingAESKey写进截图、群聊、Git或前端。

客户添加事件取得的`external_userid`只作为企微客户标识。关联CRM时必须由工作人员确认客户或家庭，不能仅凭同手机号自动合并家庭、订单或未成年人资料。

### 5. 企业微信内部应用消息

只有需要向导游、运营或管理人员发送内部待办时才创建自建应用。进入企业微信管理后台“应用管理 → 应用 → 自建 → 创建应用”，设置应用名称、图标和可见成员；创建后记录AgentId与Secret，在“我的企业 → 企业信息”记录CorpID，并将服务器公网IP `115.159.149.65` 加入可信IP。把这些值写入私有配置文件后，再由开发方接入内部待办。该通道只能发给企业成员，不能代替家长的订阅授权。

## 四、开发方接入内容

1. 把正式订阅模板ID和字段映射配置到团期通知内容，不在源码写死测试模板。
2. 小程序原生“联系客服”入口已经携带活动或订单来源卡片；绑定客服账号后完成真机收发。若以后改用企业微信客服，再替换为CorpID和客服链接调用。
3. 若启用客户联系，同步添加/删除客户事件，校验回调签名并解密消息，按事件ID幂等处理。
4. 增加企微客户与CRM客户的显式关联、解除关联和审计记录；不自动认领历史订单。
5. 若启用内部应用消息，新增独立通道和发送结果，不与家长消息状态混用。
6. 后台分别显示“任务已创建、接口已受理、发送失败、需人工处理”；没有可靠回执时不得显示“已送达”或“已读”。

## 五、必须取得的验收证据

- 真实家长微信收到报名/支付、行前变更、车辆或集合变更消息各一条。
- 拒绝订阅、模板错误、用户无授权和接口失败时，后台能看到真实原因并可人工处理。
- 小程序客服入口打开正确客服会话，客服人员实际收发一轮消息，来源活动或订单正确；若以后改用企业微信客服，再单独验证CorpID和客服链接。
- 企业客户添加事件重复推送不会生成重复CRM客户；不同家庭不会因手机号相同被错误合并。
- 导游、学校、保险和管理员账号之间不存在通知、订单或健康资料越权。
- 所有Secret、Token、EncodingAESKey和access token只存在服务器环境或本地私有交接文件中。

需填写的私有配置模板位于`private/企业微信与通知接入.local.md`。现有订阅消息操作说明见[通知与第三方相册接入操作](通知与第三方相册接入操作-20260927.md)，客服能力说明见[微信客服与手机号能力接入说明](微信客服与手机号能力接入说明-20260927.md)。
