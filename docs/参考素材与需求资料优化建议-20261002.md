# 参考素材与需求资料优化建议

日期：2026-10-02

这份建议只归纳现有需求原件、已审阅的参考界面和当前小程序已具备的能力。它不把参考产品的菜单、旧截图或本地测试结果当成新的业务需求，也不对尚未取得实际回执的支付、退款或通知做发布结论。

## 1. 报名信息的层级与分区：已有，保持克制

需求原件已明确多人员报名、缴费、退款审核和名单管理的主线，见 [`关于临安旅游集散中心研学系统（电脑与微信端）开发需求20260828.docx`](C:/Users/lenovo/Desktop/一些任务/临安文旅开发/20260914_临安旅游集散中心_需求方文档提供/关于临安旅游集散中心研学系统（电脑与微信端）开发需求20260828.docx) 中有关家长报名、退款审核与名单管理的段落；报名字段与付款前告知要求见 [`临安旅游集散中心_项目启动资料清单与业务调研模板_会议更新版_20260914(1).xlsx`](C:/Users/lenovo/Desktop/一些任务/临安文旅开发/20260914_临安旅游集散中心_需求方文档提供/临安旅游集散中心_项目启动资料清单与业务调研模板_会议更新版_20260914(1).xlsx) 的 `02_研学报名与团期`。

当前小程序已有活动、团期、参加人、联系人、健康备注与单独授权、报名确认、订单及按人退款申请。参考素材中的家长端把“活动信息—报名资料—订单进度—行前信息”依次呈现，这个信息层级值得继续保持。报名时不应因参考截图而新增身高、饮食、额外监护人等未获确认的必填字段；健康信息仍应维持可选、单独授权、可撤回的现有口径。

## 2. 登录、隐私与“我的”入口：已有，本次只补齐易理解的表达

参考素材报告已实看 5 个来源、26 张图片，其中杭州日报研学平台的手机号快捷登录、报名表单和个人中心，以及研学旅游甄选的首访隐私提示，可见完整记录于 [参考素材审阅报告](../.omo/evidence/enrollment-auto-notify-release-20261002/reference-review.md)。可借鉴的是把“游客先浏览、需要办理报名或查看个人资料时再登录”的界限讲清楚，而不是复制对方的品牌、活动图、二维码、电话、价格、优惠券或会员体系。

当前“我的”已集中登录/注册、订单、常用参加人、消息订阅与隐私入口；登录采用微信手机号快捷登录，昵称头像由用户自行选择。建议维持此范围：游客不被营销弹窗打断，登录后能明确知道哪些资料只在本机展示，哪些报名资料会用于真实业务办理。

正式的隐私、监护人、肖像、健康信息处理和营销授权文本，仍需由运营方提供并确定版本、展示位置、撤回、更正和留存规则。依据是上述启动资料的 `02_研学报名与团期`、`09_数据隐私与迁移`，以及 [`大明山（告家长书）.docx`](C:/Users/lenovo/Desktop/一些任务/临安文旅开发/20260914_临安旅游集散中心_需求方文档提供/大明山（告家长书）.docx)。告家长书可作为具体团期材料，不能替代这些正式文本。

## 3. 自动报名通知：正式模板和后端已配置，待小程序发布及真机实收

原件要求行前信息能够主动触达，并把企业微信/公众号作为触达渠道；首期不做短信营销，见启动资料的 `03_分车交通与行前` 与 `06_CRM企业微信与营销`。本次已接入**报名确认**的自动通知，正式预约成功模板与后端部署已完成，小程序发布和真机实收尚未完成：用户登录后自愿选择接收，拒绝或失败不阻断登录和报名，后续可在“消息订阅”中调整。活动提醒仍由工作人员手工发起，不作为本次自动化范围。

建议运营侧先确认报名确认的正式模板名称、发送主体和接收测试账号，再以实际结果记录“任务创建”“平台受理”“平台回执或失败”。活动提醒如需启用，应另行确定人工发送模板和责任人。在没有可用回执前，不把“平台受理”写成“已送达”或“已读”；也不在活动详情页叠加独立订阅入口，避免造成重复选择。

## 4. 订单、退款、行前与相册：已有流程，资金渠道待实际验收

需求原件要求未付款不进入正式名单、全退和部分退款均经审核并留痕；本期资料以“按取消参加人对应费用退款”为口径，见启动资料 `08_支付退款与财务` 和 [`现行资料与流程核对清单-20260921(1).docx`](C:/Users/lenovo/Desktop/一些任务/临安文旅开发/20260914_临安旅游集散中心_需求方文档提供/现行资料与流程核对清单-20260921(1).docx) 中支付、退款与财务核对的相关段落。

当前页面已经把订单状态、行前信息、退款申请进度、健康授权和已发布活动影像放在同一用户旅程中。参考素材对此可借鉴的是状态顺序清楚、主操作明确；不应加入围观人数、倒计时、促销价、储值卡、积分或虚拟币。

支付和退款的真实资金渠道仍需以商户模式、AppID 绑定、回调、证书密钥、财务执行人与对账口径的实际验收为准。现阶段把它列为待运营和外部渠道确认事项，不将缺少回执表述为已发现的确定故障。

## 5. 下一步由运营确认的最小清单

1. 每个拟上线团期的学校、年级班级、团期、报名窗口、价格、告知书版本、车辆/集合与运营账号；来源为启动资料 `12_时间节点与上线` 及 [`5.9 车辆联系单（衣锦一年级-大明山）.docx`](C:/Users/lenovo/Desktop/一些任务/临安文旅开发/20260914_临安旅游集散中心_需求方文档提供/5.9%20车辆联系单（衣锦一年级-大明山）.docx)。
2. 报名须知、隐私、监护人、肖像、健康及成人营销授权的正式文本和版本编号。
3. 报名确认的正式模板、发送人员权限和一组真实接收验收记录；活动提醒如启用，另行确认其人工发送模板和责任人。
4. 支付、全退和部分退款各一笔真实小额验收及对账记录。

在上述材料到位前，保持现有功能边界和真实数据展示即可；不需要为参考素材新增整站改版或营销功能。
