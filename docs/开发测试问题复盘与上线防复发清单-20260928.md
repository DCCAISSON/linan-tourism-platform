# 开发测试问题复盘与上线防复发清单

更新日期：2026年9月28日。本文记录已经实际遇到或复现的问题，以及以后每次测试、部署和正式上线必须执行的预防措施。未确认原因的问题不写成既定结论。

## 一、订单、支付和退款

|已遇问题|原因或边界|已经采取的措施|以后必须检查|
|---|---|---|---|
|同一订单出现多种编号，排查时用错编号|用户订单编号、系统内部ID、商户支付单号、微信交易单号用途不同|明确四类编号；后续微信账单商品描述改用用户订单编号|客服和后台查询必须注明编号类型；不得直接拿微信“商品”字段中的旧内部ID当用户订单编号|
|退款创建时报支付单号唯一键冲突|退款流水错误复用了支付流水的`out_trade_no`|退款流水不再占用支付单号；账单对账按订单重新映射原支付单号；增加回归测试|支付和退款必须使用独立商户单号；重复退款请求不得产生第二条资金指令|
|微信已退款，本地订单仍显示已支付|程序错误要求退款通知中不存在的`amount.currency`，回调返回400|按微信官方退款通知字段修复；真实回调已返回201，本地订单与名单完成结算|回调样例必须来自当前官方文档；上线前验证支付与退款回调都是2xx，并核对微信与本地状态一致|
|把“退款接口受理”误当到账|退款申请成功只表示微信受理|轮询或回调更新最终状态；本次1元退款已取得微信`SUCCESS`、本地成功及用户到账三方证据|正式退款必须同时记录商户退款单号、微信退款状态、本地结果和实际到账核对|
|APIv2与APIv3资料混用|当前代码、签名、验签和回调均按APIv3实现|固定使用APIv3密钥、商户私钥及微信支付公钥/证书|不得把APIv2密钥填入APIv3配置；更换证书或公钥必须先在隔离订单验证|
|担心误触真实退款|开发期模拟与真实资金边界不清|支付和退款使用独立服务端开关，退款由有权限工作人员明确操作|测试前固定订单、金额和人员；生产开关、账号权限和幂等键三项缺一不可|
|把“取消支付”理解为业务页还应有一次确认|小程序调用支付后由微信直接显示指纹、面容或密码支付层，业务页不能再插入自定义确认页|取消测试以关闭微信支付层为准；取消后明确提示订单仍为待支付并可再次付款|真机分别验证关闭支付层、再次支付、最终成功；取消不得扣款、生成有效名单或提前释放订单|
|服务器支付已开启，小程序仍显示“微信支付暂未开放”|支付能力同时受服务端开关和构建期环境变量控制，上传时漏传构建变量导致前后端状态不一致|取消重复的构建期支付开关，小程序统一读取服务端`/capabilities`；支付仍由服务器开关控制|每次上传前检查正式API地址并在真机待支付订单确认按钮为“发起微信支付”；不能只核对服务器环境变量|
|微信退款`ABNORMAL`被当成失败并允许重退|异常退款资金仍可能处于微信中间状态，直接标为失败会产生重复退款风险|异常状态保持本地退款申请待处理；后台改为主动查询微信结果，只有`SUCCESS`才更新名单和名额，`CLOSED`才允许按失败处理|处理中和异常人员不得再次选择退款；工作人员先在商户平台处理，再点“查询微信退款结果”|
|管理后台真实退款仍调用本地人工记账接口|开发期页面沿用了本地验证接口，生产环境会拒绝或无法实际发起微信退款|后台创建退款改用微信退款接口，待处理记录只提供微信状态查询，不再人工标记成功或失败|每次部署后从后台实际发起一笔受控退款，核对接口、微信商户平台、本地订单和用户到账四方一致|
|当日对账误判为接口故障|微信日账单不是实时生成，当日支付无法立即下载完整日账单|保留下载、哈希和差异比对能力；按交易日次日10点后执行|对账任务记录交易日期与实际执行时间；账单未生成不得伪造空账单或直接确认无差异|
|全额退款后团期统计漏计原付款|原支付状态改为 refunded，累计支付查询只计 succeeded|累计支付包含 succeeded 和 refunded，成功退款仍单独累计；不改订单或流水|通过真实数据库验证1分、带分角金额、部分及全额退款；退款前后原支付额保持，失败和处理中退款不计成功退款，按北京时间团期出发日筛选|

### 编号口径

|名称|本项目字段|用途|

## 二、微信小程序版本、登录和开发工具

|已遇问题|原因或边界|防复发措施|
|---|---|---|
|代码已上传但手机仍看到旧页面|开发版、体验版和线上版互相独立；旧体验二维码不会自动切到新开发版|每次上传记录版本号、时间和备注；设为体验版后重新生成/确认二维码；真机页面核对版本对应功能|
|微信开发者工具CLI退出码为0但实际上传失败|CLI可能在输出中打印`[error]`或`× preparing`后仍返回0；相对项目路径也可能被工具错误解析|上传必须使用小程序构建目录的绝对路径，并检查输出中出现`√ upload`和实际版本号；不能只看进程退出码|
|误以为上传后即可微信搜索|只有审核通过并发布的线上版才面向普通用户；开发版/体验版受成员范围限制|对外演示写清“体验二维码”和有效期；正式搜索只在审核发布后验收|
|体验二维码失效|二维码有有效期或对应旧版本|演示前当天重新打开版本管理确认；不把旧截图二维码作为长期入口|
|仅配置AppSecret和request域名仍无法使用|登录还依赖服务端部署、HTTPS、版本上传、体验成员和真机网络|按“AppID/AppSecret—合法域名—API健康—版本—体验成员—真机登录”顺序逐项验收|
|开发工具报`listen EACCES 0.0.0.0:9538`|本机端口占用或权限导致编译后端无法启动|关闭残留开发工具进程、检查端口占用并重启工具；该问题只在本地处理，不通过修改生产端口绕过|
|开发者工具显示`√ auto`但自动化端口仍连接失败|旧开发者工具进程和IDE服务未完全退出，新的自动化窗口没有真正监听指定端口|先用CLI执行`quit`，只清理微信开发者工具残留进程后重新启动；不得误关个人微信客户端；自动化连接成功后再开始页面断言|
|真机自动化后直接上传，可能把本地fixture地址带进正式包|原生验收脚本会重新构建小程序，并把API地址切到本地隔离服务|自动化结束后必须重新用`https://api.linantravel.cn`生产构建；上传前检索产物，要求正式域名存在且`127.0.0.1`、`localhost`不存在|
|浏览器和uni构建通过，微信仍拒绝WXSS|订单服务区使用裸伪类组合选择器，微信编译报token错误|小程序局部布局使用明确class；修改WXSS后必须通过微信实际预览/上传编译，不能以浏览器截图或uni构建成功替代；失败候选保留，新包另行冻结|
|首页强制登录、家庭码和过早索取资料造成阻力|把开发期身份关联暴露成用户步骤|当前流程改为先浏览，报名时登录并填写，家庭码退出正常流程|每次前端改版走“未登录浏览—报名—登录—资料保存—复用”的真机旅程，禁止重新引入首页资料墙|

## 三、域名、代理、服务器和HTTPS

|已遇问题|原因或边界|防复发措施|
|---|---|---|
|本机代理或fake-IP导致API域名访问异常|代理规则可能让备案域名走代理或返回虚拟IP|`linantravel.cn`和`api.linantravel.cn`保持直连并加入fake-IP排除；联调前用系统DNS确认解析到`115.159.149.65`|
|DNS记录已加但网站仍打不开|DNS、80/443安全组、Nginx、证书和应用服务是独立环节|发布后依次检查DNS、TCP 80/443、证书链、Nginx、API `/health`和具体页面，不以单项成功代替整链|
|源码已改但云端仍运行旧编译产物|只更新源码或未重启服务不能改变运行版本|部署前备份；部署后比较本地与远端编译文件哈希、重启服务、检查`systemctl`和公网健康接口|
|PowerShell生成的远程脚本带UTF-8 BOM，导致首行`set -e`未执行|带BOM脚本通过管道交给Linux Bash时，BOM会成为首个命令的一部分；后续命令可能继续执行而掩盖首行失败|远程脚本统一保存为UTF-8无BOM文件后上传并执行；同时核对归档哈希、服务状态、Nginx检查和公网健康，任何首行异常都记为部署缺陷并修正脚本|
|Windows系统`tar`处理压缩包路径失败|系统自带BSD tar会把含盘符或特定路径的目标误判为远程归档|部署归档固定使用已验证的Git GNU tar和工作区相对路径；本地归档成功并计算哈希后才允许上传，远端再次校验同一哈希|
|公网回调被鉴权或代理规则拦截|支付、企微等平台回调不能依赖人工登录态|回调路径单独检查公网可达、签名校验及2xx响应；不得通过关闭签名验证解决401/400|

|名单页面没有人员|已付款有效报名、导入教师及筛选条件来源不同；无有效数据时名单为空|演示前准备隔离团期并完成支付或明确导入；页面同时核对团期、学校、年级、班级和支付状态|

## 七、每次正式上线的强制检查

以下任一项失败，不能开放真实报名或资金：

1. 当前部署版本、编译文件哈希和小程序版本不一致。
2. 微信登录、支付、退款回调不能稳定返回2xx，或重复回调产生重复订单/退款。
3. 微信账单、商户支付单、系统订单金额或状态不一致。
4. 退款后人员名单、容量、分车、归档和保险差异未核对。
5. 家长、导游、学校、保险和管理员任一角色存在越权。
6. 页面仍含测试数据、内部说明、英文占位或错误金额。
7. 正式学校、招生范围、价格、日期、集合地点和退款规则未由业务负责人确认。
8. 本次上线范围内或已经启用的订阅消息、客服、企微、相册、保险通道只完成配置，未完成真实渠道验收。
9. 数据库未备份、迁移未核对行数或没有明确回退点。
10. 密钥、身份证、健康信息、学生名单或支付证书进入Git、日志、截图或公开文档。
