# 决策记录

## 2026-09-14

1. **独立代码仓库**：代码放入 `linan-platform`，原始合同和客户资料不纳入Git。原因是这些材料包含商业信息且不属于可构建源码。
2. **单仓库模块化单体**：小程序、后台、API和共享契约使用一个Git仓库；后端先保持单体，数据库统一为MySQL 8.4 LTS。原因是当前交付期短，接口和数据模型需要高频同步。
3. **统一TypeScript与Vue前端**：小程序使用uni-app + Vue 3，后台使用Vue 3，API使用NestJS。原因是Codex并行开发时语言切换更少，共享契约更直接。
4. **开源组合而非旅游整仓改造**：采用成熟框架、组件和后台壳，旅游整仓只参考业务。原因是现成旅游项目普遍过重、过旧或缺少支付与未成年人数据保护。
5. **先模拟支付，后真实接入**：业务订单与支付适配分离。原因是名称、AppID、商户号和域名尚未到位，但订单和名单链路可以先验证。
6. **C盘本地主开发，腾讯云用于远程开发、联调和部署**：C盘清理历史记录曾达到47.11GB可用；2026-09-15安装前复核约36.78GiB，并通过实时 `(Get-PSDrive -Name C).Free -ge 35GB` 闸门。依赖安装前必须重新测量，低于该闸门即停止。企业腾讯云账号可另建Cloud Studio或开发云服务器，但不得与生产服务器共用；云数据库MySQL和COS分别保存结构化数据与文件，开发、测试、生产资源相互隔离。E盘修复前不迁移仓库、Docker或MySQL数据，其状态不再阻断项目开工。
7. **以授权时刻T0计算内部工期**：Codex连续执行三条代码线，目标为T+24小时完成当前已确认范围代码、T+72小时形成带证据的UAT候选版、T+3—5天形成稳定版。合同日期继续作为外部最迟节点；未确认规则、正式账号和真实支付保持独立闸门，不以赶工代替验收。
8. **业务文档使用中文文件名**：`docs/`中的八份业务与管理文档统一改为中文名，便于项目成员识别；`README.md`、`DESIGN.md`、配置文件和`.omo`计划标识保留标准英文名，避免破坏工具发现规则。每次改名同步更新全仓路径引用。
