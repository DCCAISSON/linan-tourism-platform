## 6人游界面判断

公开页面显示其核心结构是“大图建立旅行氛围 + 极短需求表单 + 单一主按钮 + 服务优势 + 四步服务流程 + 顾问信任信息”。这套信息层级可以参考，但页面、图片、Logo、文案和源代码属于其自身资产，不能直接复制。

本项目适合吸收的交互原则：

- 首页只有一个主要任务，家长能立即进入所属学校或团期；
- 首屏先呈现团期日期、适用学校、价格和报名截止时间；
- 多孩报名采用分步表单，减少单屏字段密度；
- 提交后明确显示“待支付、已支付、待核对、已退款”等状态；
- 行前信息采用时间线，重要联系人和紧急电话固定可达；
- 用真实资质、服务流程和联系方式建立信任，不堆砌营销卡片。

不适合照搬的部分：

- 6人游以定制咨询和旅行顾问转化为核心，本项目首先是学校团期报名和缴费；
- 大幅营销图片不能压过学校、班级、参团人和付款状态；
- “提交手机号等待顾问联系”不适合替代本项目的即时报名闭环。

## 引入流程

1. 固定官方仓库URL、提交SHA和许可证。
2. 在隔离临时目录运行依赖审计和构建，不直接覆盖本仓库。
3. 只抽取当前范围需要的页面骨架或组件，不保留示例业务、默认账号和无关依赖。
4. 在 `third_party` 登记来源、文件和改动，并保留要求的许可证声明。
5. 合入后运行类型检查、测试、真实界面检查和依赖漏洞检查。
