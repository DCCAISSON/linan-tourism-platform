# 微信客服、登录与手机号能力接入说明

更新日期：2026-10-02。本说明记录首版实际上线的用户路径、可选后备能力和验收前提；不代表外部配置、部署或真实消息投递已经完成。

## 一、首版用户登录、注册与资料策略

1. 用户侧首版只提供微信手机号快捷登录。小程序在用户点击并同意后，以 `wx.login` 的 `loginCode` 和 `getPhoneNumber` 的一次性 `phoneCode` 调用 `POST /wechat/miniapp/phone-login`。成功后获得已验证手机号的会话，生产环境的新报名提交才可继续。
2. 普通微信身份登录 `POST /wechat/miniapp/login` 保持可用，用于浏览和恢复既有身份；它不代替生产新报名所需的手机号验证。
3. 登录完成后，用户可自行决定是否订阅报名和活动通知；订阅授权与登录后的同一用户流程衔接，不应预先勾选、代替用户同意或阻断登录、浏览和报名。
4. 昵称与头像也是可选资料。用户选择头像、填写昵称并点击保存后，小程序才以 `family:${familyCode}` 为隔离键将昵称和本地头像路径保存到本机，只在“我的”页展示。用户可跳过，资料不参与登录、报名、订单或身份识别。
5. 当前没有后端用户资料接口，也不上传该头像到 COS。清除小程序本地数据、重装或换设备后，昵称和头像不会保留或同步；这是当前单设备展示范围的已知限制。

微信原生 `chooseAvatar` 和 `type="nickname"` 只用于用户主动选择和填写，不能自动读取微信头像或昵称。实施时以[微信小程序用户信息与头像昵称说明](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/userProfile.html)为准，并保持页面中的明确保存动作。

## 二、报名和活动订阅消息配置

小程序管理员先在微信公众平台“功能 → 订阅消息”从公共模板库选择正式模板，并在“我的模板”取得 `templateId` 与模板原始字段名。当前项目没有模板编辑界面；具全局 `notifications.write` 权限的人员须从受信任后台来源调用 `PUT /staff/user-notifications/templates/:id` 写入模板。写入字段为 `title`、`category`、`templateId`、`type: "once"`、`enabled` 及 1 至 5 个 `fields`。每个字段的 `key` 必须与正式模板的 `thingN`、`numberN` 或 `timeN` 原字段名一致，不能按中文含义猜测。

报名成功自动通知使用 `category: "enrollment"`、`enabled: true`、`type: "once"` 的正式模板。当前正式模板为标题“预约成功通知”、templateId `g4vOTMwPwXZCV636hzQjSsv7SplCumn4LjGADFzB4Fs`，其 `fields` 必须恰好为 `key: "thing5", label: "线路名", rule: "thing"`、`key: "number4", label: "人数", rule: "number"`、`key: "time1", label: "预约时间", rule: "time"`。为兼容既有配置，服务仍支持完整的“活动名称／报名人数／活动时间”字段组；两组字段不能混用。字段不完全匹配、存在多个匹配模板或用户没有该模板的有效订阅时，系统不创建自动任务。

登录面板只读取 `enabled === true` 且当前用户尚未处于 `active` 状态的模板：`category: "enrollment"` 用于报名提醒，`category: "activity"` 用于活动提醒；每类最多显示一个。其它通知类别不进入该登录面板，也不影响既有业务入口。

没有上述启用模板时，不弹出原生订阅框，登录和报名继续完成，也不宣称用户已订阅。用户明确点击接收提醒后才调用原生 `requestSubscribeMessage`；登录同意、手机号授权或跳过都不代表订阅同意。报名确认后，满足上述模板与订阅条件时系统创建一次性自动任务，并每 60 秒恢复处理仍为待发送的任务。活动提醒和其它类别仍由具 `notifications.send` 权限的人员在既有后台选择模板、创建任务并明确发送，不会自动群发。

自动发送在调用微信接口前先占用一次性订阅资格；接口结果为 `unknown` 时，系统保留未知结果供人工核对，不自动重发，以免重复投递。工作人员应根据任务和微信侧记录核对后再决定处置。

## 三、短信能力是未启用的后备路径

服务端仍保留以下短信后备接口：

- `POST /wechat/miniapp/sms/send`
- `POST /wechat/miniapp/sms-login`

首版小程序没有短信入口，因此腾讯云短信、签名、模板和额度不是首版微信手机号快捷登录的上线前置条件。不得因为这些接口存在而在首版验收中要求真实短信发送。

如以后决定启用短信后备，须先完成腾讯云短信资质、签名、模板、额度和真实投递验收，再在用户界面提供入口。模板参数顺序为验证码和有效分钟数；验证码有效期为 5 分钟。缺少任一短信配置时服务端返回 `sms_unconfigured`，不得向用户显示“已发送”。短信路径还应验收同号码 60 秒冷却、错误码五次限制、过期、重放和服务端拒发。

## 四、部署前变量

所有值只写入部署环境的秘密管理服务或被忽略的私密配置文件，不写入 `.env.example`、小程序包、文档或工单。

| 用途 | 变量 | 首版是否需要 |
| --- | --- | --- |
| 微信身份与一键手机号 | `WECHAT_MINIAPP_APP_ID`、`WECHAT_MINIAPP_APP_SECRET` | 需要 |
| 微信订阅消息与报名成功自动任务 | `WECHAT_SUBSCRIBE_ENABLED=true`，优先复用 `WECHAT_MINIAPP_APP_ID`、`WECHAT_MINIAPP_APP_SECRET` 获取微信访问令牌 | 配置正式模板并启用自动任务时需要 |
| 手机认证 HMAC | `PHONE_AUTH_HMAC_KEY`，至少 32 个字符 | 需要 |
| 腾讯云短信后备 | `TENCENT_CLOUD_SECRET_ID`、`TENCENT_CLOUD_SECRET_KEY`、`TENCENT_CLOUD_SMS_APP_ID`、`TENCENT_CLOUD_SMS_SIGN_NAME`、`TENCENT_CLOUD_SMS_TEMPLATE_ID`；`TENCENT_CLOUD_REGION` 未设置时为 `ap-shanghai` | 仅启用短信后备时需要 |

`PHONE_AUTH_HMAC_KEY` 用于手机号、来源和验证码的 HMAC-SHA-256 摘要。缺少该密钥时手机认证安全失败；普通微信身份登录不依赖它。手机号、验证码、会话令牌和云密钥不得写入日志、截图、工单或版本库。

部署数据库时执行手机认证迁移 `1766020000000-AddPhoneAuthentication`。它新增会话手机号验证字段及手机号身份、短信挑战和限流表；迁移前按既有部署流程备份数据库，不手工填写摘要字段。

## 五、微信小程序配置与首版验收

1. 管理员登录[微信公众平台](https://mp.weixin.qq.com)，进入实际小程序账号，确认主体、AppID 和手机号快速验证能力符合微信当前要求。
2. 确认隐私保护指引中的手机号处理目的与登录、报名用途一致，并核对一键手机号能力的可用额度。微信手机号能力和腾讯云短信额度分别管理。
3. 上传含本轮功能的新体验版，在成员管理中添加测试者。旧包不包含本轮登录和资料流程。
4. 测试者在真实微信中先拒绝一次手机号授权，确认不能绕过生产报名验证；再同意授权，确认进入原目标页，重新进入后会话仍可用。
5. 在登录完成页分别验证：可跳过昵称头像；主动选择头像、填写昵称、点击保存后“我的”页显示；本机切换另一个家庭身份时不串资料。资料不会跨设备同步，属于预期行为。
6. 配置两类正式模板后，用户可选择订阅报名和活动提醒；拒绝订阅不会影响登录或报名。未配置模板时不显示原生订阅框、不宣称已订阅。对匹配三字段契约且已获同意的报名订阅，验收报名确认后自动任务创建、60 秒恢复处理，以及 `unknown` 结果只供人工核对、不自动重发；活动自动发送不在本轮范围。

微信手机号能力以[官方 getPhoneNumber 文档](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/getPhoneNumber.html)为准。

## 六、腾讯云短信后备启用验收

仅在产品决定开放短信入口后执行：

1. 由运营主体在[腾讯云短信控制台](https://console.cloud.tencent.com/smsv2)完成资质、签名、模板和应用配置，并将 API 凭证映射到第四节变量。
2. 使用已审核的验证码模板，核对两项参数为验证码和有效分钟数；签名单独配置，不重复写入正文。
3. 在隔离或预发布环境完成真实收码、登录、错误码、60 秒重复发送限制和腾讯云回执核对。控制台“请求已受理”不等于手机已收到短信。
4. 完成真实投递验收后，才可发布小程序短信入口。

[腾讯云国内短信入门](https://cloud.tencent.com/document/product/382/37745)和[资质与使用要求](https://cloud.tencent.com/document/product/382/13444)为配置依据。

## 七、微信客服人员设置

当前小程序使用原生 `button open-type="contact"`，不需要为该入口另建企业微信客服系统。

1. 小程序管理员在微信公众平台客服功能中绑定接待人员微信。
2. 接待人员使用已绑定微信打开官方“客服小助手”，选择本小程序并切换为在线。
3. 使用另一测试微信在体验版活动详情点击“咨询”，选择主题后实际发送一条测试消息；只打开会话不算发送成功。
4. 接待端接入并回复测试消息，用户端收到回复后才算双向收发通过。
5. 若失败，依次核对客服在线状态、绑定账号、消息推送和第三方客服配置；未经核对不关闭已有消息配置。

依据：[微信小程序客服消息使用指南](https://developers.weixin.qq.com/miniprogram/introduction/custom.html)。

## 八、当前边界

手机认证、短信后备接口、迁移和限流已在代码中实现，但外部微信授权、真实客服收发和真实短信投递不会因本文自动完成。当前安全审查记录见[final-security-review.md](../.omo/evidence/task-7-miniapp-ui-phone-consultation-20261001/final-security-review.md)。生产开放前以更新后的安全审查、真实微信手机号验收和客服验收为准；短信只在另行启用后追加真实短信验收。
