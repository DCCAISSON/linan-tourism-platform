# 皓石云系统只读调研记录

调研日期：2026-09-22
调研范围：需求方提供的皓石云管理后台账号，仅查看菜单、列表字段、筛选条件和表单结构。未执行新增、编辑、退款、删除、导出或其他会改变业务数据的操作。

## 一、可以直接用于本项目的业务结构

### 1. 活动、场次和价格规格分层

皓石云将业务拆为三层：

1. **活动**：维护海报、标题、副标题、活动位置、参与人员、活动类别、年龄、天数、原价、最低价、活动详情、安全行程、活动须知等长期内容。
2. **场次**：维护开始日期、开始时间、结束日期、结束时间、场次名和报名截止天数。
3. **参与人规格**：维护规格名称、价格、会员价、成人数量和儿童数量。

这一结构可以作为本项目“课程/活动—团期—学校价格或人员规格”的参考。现有项目已经具备活动、团期和学校价格基础，后续应补齐成人/儿童容量、报名截止时间以及规格与人员数量的明确关系。

### 2. 参与人级别的执行字段

场次参与人列表包含以下执行字段：

- 导游
- 车牌号
- 信息核对：未确认、待确认、已确认
- 是否进群：未进群、已进群
- 签到：未签到、已签到
- 邮寄：未邮寄、已邮寄
- 保险单号
- 用户备注、后台备注

这些字段说明执行管理应落到具体参与人，而不应只保存班级人数汇总。它们可以直接用于完善本项目的人员级车辆分配、导游工作台、签到和执行状态。

### 3. 行前助手

皓石云的行前助手分为活动级默认信息和场次级信息，主要字段包括：

- 群二维码
- 领队联系方式
- 行李清单
- 行前须知
- 出行合同
- 统一出行方式
- 统一出发集合时间、集合地点
- 自行前往集合时间、集合地点

本项目可沿用“活动默认值＋团期覆盖值”的思路，并在家长端订单详情中集中展示这些信息。

### 4. 订单与退款状态

订单状态包括：待付款、已付款、待评价、已完成、退款中、已退款、已关闭。支付方式包括微信和手动。

退款页面采用以下方式：

- 人工输入退款金额
- 输入操作密码
- 选择退款原因
- 填写备注
- 发起微信退款

退款原因包括客户个人原因、返还优惠、未成团、客诉退费、协商退费等。

皓石云页面没有发现“勾选取消人员后自动计算退款金额”的操作。因此，本项目不照搬人工金额模式，仍按已确认规则实现：选择取消人员，按人数计算退款金额，不按提前天数扣费；后台保留退款原因、备注和操作权限校验。

### 5. 后台账号

皓石云新增账号时只有角色、用户名和密码三个字段，固定角色为：

- 管理员
- 业务员
- 财务

页面没有发现创建账号时逐项勾选功能权限的设置。该模式可作为角色预设参考，但不能覆盖本项目已确认的“主账号创建子账号、勾选权限、设置数据范围和有效期”要求。本项目现有细粒度权限方案应继续保留。

### 6. 保险、评价和内容

保险列表记录保险状态、保险单号、订单号、参与人类型、姓名、性别、生日、证件类型和证件号码，状态至少包括正常和已退保。

评价列表包含状态、精选、置顶、参与人、活动、场次、评星、图片、评论和提交时间。

活动视频采用视频号 ID、视频 ID、海报图和置顶状态管理，可作为以后接入微信视频号内容的字段参考。

### 7. 班级与财务

班级列表包含阶段、学校、入学年份、年级、班名、班级基金、成员人数、创建人、创建时间和是否公开。

资金明细包含用户、资金类型、金额、订单类型、订单号、时间和描述。数据看板主要展示浏览人数、成交金额、金额环比，以及最近 7 天、30 天、60 天趋势。

## 二、对当前开发任务的直接影响

建议按以下顺序吸收皓石云中已经验证过的业务字段：

1. **退款闭环**：退款申请、取消人员选择、按人数计算、审批或确认、退款中/已退款状态，以及名单和名额联动。
2. **人员级执行管理**：为参与人增加导游、车辆、信息核对、进群、签到和执行备注，并支持批量设置及导出。
3. **行前助手与家长端展示**：补充群二维码、领队联系方式、资料附件、统一出行和自行前往信息。
4. **保险工作台**：先实现投保资料校验、投保状态、保单号、退保状态和导出，外部保险接口以后接入。
5. **评价管理**：实现评星、文字、图片、审核、精选和置顶；按合同要求再补充评价统计与导出。
6. **内容附件**：使用现有 COS 保存海报、行李清单、行前须知、合同和评价图片。

## 三、不建议照搬的部分

- 皓石云参与人证件、手机号等信息直接出现在后台表格中。本项目应继续采用脱敏展示、权限控制和操作审计。
- 皓石云多个字段可在列表中直接修改，删除等操作也紧邻业务数据。本项目应对退款、删除、账号权限等高影响操作保留确认和权限校验。
- 皓石云账号权限只有固定角色。本项目需要角色预设与具体权限勾选并存。
- 皓石云退款金额由工作人员手填。本项目应按取消人员自动计算，避免金额与名单不一致。
- 皓石云数据看板以浏览量和成交额为主。本项目后台还需要团期、学校、已付款人数、待核对名单、车辆和保险等执行指标。

## 四、皓石云界面仍不能回答的问题

以下内容无法仅通过现有后台页面确认，仍需要需求方给出实际规则：

- 谁可以发起和批准退款，退款失败后由谁处理。
- 退款完成后，参与人何时移出名单，名额何时释放。
- 导游是否使用单独账号、小程序或其他移动端，以及可查看的数据范围。
- 保险接口服务商、投保失败和退保失败处理方式。
- 图片直播服务商、相册权限和数据保存期限。
