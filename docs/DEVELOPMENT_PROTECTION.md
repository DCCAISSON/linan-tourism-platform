# 开发保护与恢复规则

## 仓库边界

本仓库只保存源码、迁移、测试、部署模板和技术文档。合同、营业执照、身份证、学生名单、健康信息、支付证书、生产数据库、导出报表和活动照片保留在受控业务存储中。

## 已启用的本地保护

- `.gitignore` 排除环境文件、证书、客户数据、日志、构建产物和备份。
- `.githooks/pre-commit` 阻止常见密钥/证书路径、客户数据目录、备份文件和超过10MB的文件进入提交。
- `.gitattributes` 固定文本行尾并标记二进制文件，降低Windows环境下的无意义变更。
- Git本地配置使用 `.githooks`、只允许快进拉取，并在拉取时清理失效远端引用。
- 新克隆必须运行 `npm run repo:setup` 恢复上述本地Git配置，再运行 `npm run repo:verify` 检查保护状态。

## 分支与提交

- `main` 始终保持可构建、可部署；远端建立后禁止直接推送。
- 功能分支：`feat/<module>-<result>`；修复分支：`fix/<module>-<cause>`。
- 一个提交只包含一个可独立回滚的结果；数据库迁移与直接使用它的代码同一提交。
- 不使用强制推送覆盖共享分支；必要时仅对个人分支使用 `--force-with-lease`。
- 每次合并前查看完整差异、暂存文件和构建/测试结果。

## 远端保护

创建私有GitHub或Gitee仓库后，为 `main` 启用：

- 仅通过Pull Request合并；
- 必须通过类型检查、测试、构建和秘密扫描；
- 禁止强制推送和删除主分支；
- 要求线性历史；
- 自动删除已合并功能分支；
- 第二个远端只作只读镜像或灾备，不在两个远端分别开发。

## 密钥和账号

- 本地真实参数只放在被忽略的 `.env`，生产参数放腾讯云密钥管理或服务器环境变量。
- 微信支付私钥、API v3密钥、AppSecret和腾讯云SecretKey不得出现在聊天记录、Issue、Git差异、日志或截图中。
- 对方通过微信后台角色、腾讯云子账号和支付平台技术人员角色授权，不共享主账号密码。
- 密钥泄露时先撤销/轮换，再清理历史；仅从最新提交删除文件不足以消除泄露。

## 数据保护

- 本地和测试环境只使用虚构人员数据。
- 未完成人员数据权限验证前，不导入真实未成年人资料。
- 数据库迁移禁止静默删除、聚合、填补或重编码数据；会改变样本或业务记录的迁移必须附数量核对和回滚方案。
- 支付、退款、权限变化和协议确认必须有审计记录，日志不得记录完整身份证号、健康内容或密钥。

## 备份与恢复

| 对象 | 频率 | 保存位置 | 恢复方式 |
| --- | --- | --- | --- |
| Git源码 | 每次完成任务即推送 | 私有主远端 + 镜像远端 | 从受保护分支或标签恢复 |
| 本地未合并工作 | 每日结束 | 推送个人分支 | 从远端分支恢复 |
| 开发数据库 | 每日或重大迁移前 | E盘受控目录，不进Git | 新库恢复后核对记录数 |
| 生产数据库 | 上线后自动备份 | 腾讯云跨日备份 | 定期在隔离环境做恢复演练 |
| COS文件 | 开启版本控制/生命周期 | 腾讯云COS | 按版本恢复，删除使用延迟策略 |

## 发布闸门

以下任何一项失败都不能开放真实报名：金额或名单不一致、重复支付/退款、越权读取、缺少监护人授权记录、生产回调不可验证、支付账单无法对账。
